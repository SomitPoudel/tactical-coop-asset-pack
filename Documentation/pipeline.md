# Pipeline status and execution

The supported runtime is **Blender 3.6 LTS**. The scripts use metric units, an explicit World shader, stable material identifiers, script-relative imports, explicit dimensions, real armature modifiers, named actions, and collection-scoped FBX export.

## Repeatable quality-sample command

From the repository root:

```bash
BLENDER_BIN=blender Scripts/run_quality_sample.sh
```

Equivalent commands:

```bash
blender -b --python Scripts/generate_quality_sample.py -- --validate
blender -b Sources/quality_sample.blend --python Scripts/export_to_unity.py -- --validate
```

The first command writes `Sources/quality_sample.blend`, `Previews/quality_sample.png`, and `Documentation/quality_validation.json`. The second writes FBX files under `Characters/`, `Equipment/`, and `Environment/`.

## Unity orientation

FBX export uses `axis_forward='-Z'`, `axis_up='Y'`, applies metre scale, excludes showcase lights/camera/reference geometry, and preserves the shared armature/actions. In Unity, inspect the importer's scale factor, Humanoid avatar mapping, materials, and clip loop flags. Unity validation is untested unless a Unity project is supplied.

## Current implementation tracking

- Implemented quality sample: officer, rig, weighted mesh parts, carbine with separate magazine and attachment empties, room with open double doorway, independent hinged leaves and collision proxies, seven distinct sample actions, render, measured validation, FBX export.
- Partial expansion: crate, pallet, shelving, barrel, desk, locker and extinguisher are generated by `generate_full_pack.py`.
- Missing/partial: suspect and civilian full humanoid clothing variants, remaining equipment and architecture, contact-sheet compositor, and Unity-side automated import test.
- Animations after the sample (strafe, backward, interaction, surrender, hostage cower, revive) remain to be authored.

No binary output or visual/Unity test is claimed until the launcher is run on a machine with Blender and, optionally, Unity.
